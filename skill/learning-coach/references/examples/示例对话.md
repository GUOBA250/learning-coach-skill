## 第 1 题：如何理解 OSI 七层模型？

### 一、通俗讲解

OSI（Open System Interconnect）是国际标准化组织提出的一个网络分层模型，全称是"开放式通信系统互连参考模型"。它把计算机网络体系结构划分为七层，每一层实现各自的功能和协议，并完成与相邻层的接口通信。

为什么要有分层？因为网络通信太复杂了，一次性讲清楚所有细节根本不可能。分层之后，每一层只负责自己的事，层与层之间通过接口通信，各司其职。

想象你寄快递：你只需要把东西装进箱子、写地址（应用层），剩下的快递公司自己安排（传输、运输、分发）。你不需要知道快递车怎么走、分拣中心怎么操作。网络分层也是这个思路。

这七层从下到上是：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。

### 二、流程图（文字版）

```
OSI 七层模型
    │
    ├── 应用层（第七层）：为应用程序提供服务，如 HTTP、DNS、SMTP
    ├── 表示层（第六层）：数据压缩、加密、描述
    ├── 会话层（第五层）：建立、管理、终止会话
    ├── 传输层（第四层）：为两台主机进程提供通信服务，如 TCP、UDP
    ├── 网络层（第三层）：路由和寻址，如 IP
    ├── 数据链路层（第二层）：相邻节点之间传帧，如 MAC
    └── 物理层（第一层）：比特流传输，硬件相关
```

### 三、核心答案（75-80 分标准版）

OSI 是国际标准化组织提出的网络分层模型，全称是"开放式通信系统互连参考模型"，把计算机网络体系结构划分为七层。每一层实现各自的功能和协议，并完成与相邻层的接口通信。

**七层从下到上**：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。

**物理层**：实现计算机节点之间比特流的透明传送，与硬件相关。**数据链路层**：在相邻节点之间传帧，包含 MAC 地址。**网络层**：负责路由和寻址，核心协议是 IP。**传输层**：为两台主机进程之间的通信提供服务，主要协议是 TCP 和 UDP。**会话层**：负责建立、管理和终止会话。**表示层**：数据压缩、加密和描述。**应用层**：为不同的网络应用提供服务，如 DNS、HTTP、SMTP。

**数据在各层之间的传输**：发送方从应用层往下，每层加自己的首部信息，封装成数据帧、比特流。接收方从物理层往上，逐层解封，还原出原始数据。

### 四、面试官可能的追问

**追问 1：TCP/IP 和 OSI 有什么区别？**

TCP/IP 是四层或五层结构，把 OSI 的会话层、表示层、应用层合并成了应用层。TCP/IP 没有对网络接口层细分，只是概念性描述。TCP/IP 是实际应用的标准，OSI 是理论参考模型。

**追问 2：为什么 TCP/IP 要去掉表示层和会话层？**

因为会话层、表示层、应用层都是在应用程序内部实现的，最终产出的是一个应用数据包。应用程序之间几乎无法实现代码的抽象共享，所以 OSI 设想中的应用程序维度的分层无法实现。

**追问 3：数据在各层之间怎么传输？**

发送方从应用层往下，每层加自己的首部信息。应用层报文被传到传输层，加上传输层首部形成报文段。再传到网络层，加上网络层首部形成数据报。再传到数据链路层，加上 MAC 地址形成数据帧。最后物理层封装成比特流传输。接收方从物理层往上，逐层解封。

## 🎯 卡哥式思路：这道题在考什么

题目：给字符串 `s` 和 `t`，在 `s` 里找一个**最短的连续子串**，要求它**包含 `t` 里所有字符**（顺序无所谓，但每个字符的数量要够）。

**和 438 字母异位词的区别**：438 是固定长度窗口，76 是可变长度窗口。

**关键词**：连续子串 + 覆盖所有字符 → 滑动窗口。

---

## 🎯 核心思路

**窗口扩张**：右指针向右走，把字符纳入窗口，直到窗口覆盖了 `t` 的所有字符。

**窗口收缩**：一旦覆盖了，左指针向右走，尽可能缩小窗口，同时保持"仍然覆盖"。缩到不能再缩了，记录这个窗口，然后再扩张。

用 `need` 记录 `t` 里每个字符需要多少个，`window` 记录当前窗口里每个字符有多少个。用 `valid` 记录有多少种字符的数量已经满足要求。

---

## 🎯 完整代码

```js
var minWindow = function(s, t) {
    const need = new Map()
    const window = new Map()

    for (const c of t) {
        need.set(c, (need.get(c) || 0) + 1)
    }

    let left = 0
    let right = 0
    let valid = 0
    let start = 0
    let len = Infinity

    while (right < s.length) {
        const c = s[right]
        right++
        if (need.has(c)) {
            window.set(c, (window.get(c) || 0) + 1)
            if (window.get(c) === need.get(c)) {
                valid++
            }
        }

        while (valid === need.size) {
            if (right - left < len) {
                start = left
                len = right - left
            }

            const d = s[left]
            left++
            if (need.has(d)) {
                if (window.get(d) === need.get(d)) {
                    valid--
                }
                window.set(d, window.get(d) - 1)
            }
        }
    }

    return len === Infinity ? '' : s.substr(start, len)
};
```

---

## 🎯 一行一行拆

- `right++` 放在 `s[right]` 之后，是为了让 `right - left` 直接表示窗口长度（左闭右开）。
- 如果 `c` 不在 `t` 里，直接跳过，不进 `window`。
- `window.get(c) === need.get(c)`：这个字符的数量**刚好**满足要求，`valid++`。注意是 `===`，不是 `>=`。
- 收缩时先记录当前窗口，再左移 `left`。**注意顺序**：先判断再减，否则判断条件永远为 false。

## 🎯 卡哥式易错点总结

| 易错点 | 说明 |
|---|---|
| `right++` 的位置 | 放在 `s[right]` 之后，表示左闭右开 |
| `valid++` 时机 | 只在该字符数量**刚好等于** need 时 +1，不是 ≥ |
| `valid--` 时机 | 出窗口前判断，如果当前数量刚好等于 need，说明一出就不满足了 |
| 不在 t 里的字符 | 不进 window，不参与 valid |

## 第 1 块：`createParserContext` + `advanceBy`

### 为什么要写这两个函数？

`createParserContext` 把字符串装进一个对象里，属性名叫 `source`。因为解析过程中要不断修改 `source`，用对象包着方便共享和修改。

`advanceBy` 是"从头部砍掉 length 个字符"。解析器一直在往前走，每次消费掉已经解析的部分。

```ts
function createParserContext(content: string) {
    return {
        source: content
    }
}

function advanceBy(context: any, length: number) {
    context.source = context.source.slice(length)
}
```

**第 1 行**：定义函数，接收模板字符串 `content`。

**第 2 行**：返回一个对象。

**第 3 行**：对象的属性叫 `source`，值就是传进来的 `content`。

**大白话**：就是把字符串装进一个对象里。

---

### 用例子跑一遍

模板 `<div>hello</div>`

**初始**：`context = { source: '<div>hello</div>' }`

**解析完 `<div>` 之后**：`context = { source: 'hello</div>' }`

**解析完 `hello` 之后**：`context = { source: '</div>' }`

**解析完 `</div>` 之后**：`context = { source: '' }`

## 📝 复习题

**Q1：`createParserContext` 是干什么的？**

A：把模板字符串装进一个对象，属性叫 `source`。

**Q2：`advanceBy` 是干什么的？**

A：从 `source` 头部砍掉 length 个字符。

**Q3：为什么用对象包着 source，而不是直接传字符串？**

A：因为解析过程中要不断修改 `source`，用对象包着方便共享和修改。

**Q4：`slice(length)` 为什么相当于"砍掉 length 个字符"？**

A：字符串索引 0 到 length-1 正好是 length 个字符。从索引 `length` 开始截，前面 length 个字符被跳过了。

**Q5：`advanceBy` 的第二个参数是"要砍掉多少个字符"还是"截到哪个索引"？**

A：是"要砍掉多少个字符"。传 `content.length` 比传 `endIndex` 更符合语义。

**Q6：为什么要砍 source？**

A：让 `source` 永远只保留"还没解析的部分"，每次只看开头就行，不用维护额外的位置指针。
