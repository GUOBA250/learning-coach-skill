# 每日学习计划规范（面试倒计时模式）

## 何时使用

当用户说：

- "帮我定个学习计划"
- "我还有 X 天面试"
- "面试倒计时，每天该学什么"
- "我每天能学 X 小时，帮我安排"
- "做个冲刺计划 / 备考计划"
- "帮我规划一下这几周"

## 第一步：先收集三个信息，不直接排计划

缺哪个问哪个，**一次问完**，不要挤牙膏：

1. **距下次面试还有几天**（或具体面试日期）。有没有笔试、几轮面试，知道就一起问。
2. **每天能拿出多少学习时间**。工作日和周末不一样，就分开说；只给一个数就按每天一样算。
3. **当前三围基础**，每项让用户自己选档位：
   - **八股**：没背过 / 背过一部分 / 大部分背过
   - **算法**：没刷过 / 刷过一些（几十道）/ Hot100 刷过大半
   - **项目**：讲不清 / 能讲流程但难点讲不深 / 能讲清难点和自己的贡献
4. **学习风格 3 题（与三围同一次问完，决定项目读码轨道）**：按 `任务先行规范.md` 第一节问诊——纯听讲能记住几成、最近一次"懂了"的瞬间怎么发生的（动手/听讲/类比画图）、图/类比/纯文字哪个最有效。构造型走任务先行轨道，听讲型走逐行带读，信号不明确默认听讲型；定计划阶段先记录结论，第一次读项目时直接用，不再重问。

可选追问（用户不说就不追问）：目标岗位和方向（如前端 Vue 岗）、已经知道的薄弱章节。

## 第二步：算总账

- 总可用时长 = 工作日时长 × 工作日天数 + 周末时长 × 周末天数。
- **扣掉 10% 弹性时间**，真正排进计划的时间按 90% 算。计划排太满 = 必崩。
- 算法是手撕硬门槛：**哪怕时间再紧，每天至少 1 道，保持手感。**

## 第三步：定三围时间配比

三围按档位分配权重：**弱 = 3 份，中 = 2 份，强 = 1 份**。

- 每个维度最低保留 15%。强项可以少排，但不能断，断了会忘。
- 每天内部的新旧比例：
  - 打底/强化期：80% 学新 + 20% 复习。
  - 冲刺期：20% 学新 + 80% 复习。
- **考前最后 3 天不学任何新东西**，全部复习 + 模拟面试。
- 冲刺期安排 **2 次全流程模拟面试**，流程、评分、复盘统一按 `模拟面试规范.md` 执行（第一次摸底找问题、第二次考前 2-4 天复测错题本里未出库的点）；计划里写到"模拟面试"时直接引用，不另造玩法。

## 第四步：按倒计时选打法

| 剩余天数 | 打法 | 取舍策略 |
|---|---|---|
| ≥ 30 天 | 系统打底 | 八股按章节完整过，算法按题型刷，项目慢慢挖深，冷门可以看 |
| 14-29 天 | 重点突破 | 八股只背高频，算法主攻 Hot100 高频题型，项目准备 3 个 STAR 故事 |
| 7-13 天 | 高频速通 | 放弃冷门章节，八股高频题 + 算法高频 50 题 + 项目逐字稿 |
| ≤ 6 天 | 抢救模式 | 只做 ROI 最高的事：八股背高频现成答案，算法每天 2-3 道保手感，项目写逐字稿背熟 |

时间排不下时**直接告诉用户必须放弃什么**，不许诺"X 天保证上岸"。

## 第五步：切三阶段

不管剩多少天，都切成三段，天数按约 5:3:2 分配：

1. **打底 / 补弱阶段（约 50%）**：时间向弱项倾斜，目标是把每块补到"能开口"。
2. **强化阶段（约 30%）**：成套刷题、章节串联、项目深挖难点和手写题。
3. **冲刺阶段（约 20%，含最后 3 天）**：错题本滚动复习、模拟面试、查漏补缺，不学新内容。"错题过两遍"= 把库存全部推到第 3 档（7 天）以上；考前 3 天只复习 🔴 和钉子点。

## 第六步：排每天的任务

- 按"块"切，**1 块 = 30-45 分钟**，块之间休息 5-10 分钟。
- **番茄钟保护**：单个块预计超过 50 分钟（如算法大题）时，块内按 25 分钟专注 + 5 分钟离开座位切开，任务表里直接写成"25+5+25"而不是一整块；连做两个番茄后必须休息，防久坐式疲劳。
- 按每天可学时长定块数：
  - ≤ 1.5 小时：最多 2 块，只排当天最高优先级。
  - 2-3 小时：3-4 块。
  - ≥ 4 小时：5 块以上，文理穿插，别把 3 块算法排一起。
- 每块必须写清四件事：**学什么、用什么材料、产出标准、预计时长**。
  - 产出标准必须能验收，比如"能脱稿讲出 Vue 响应式流程"；不能写"看一下 Vue"这种没法检查的。
  - 八股/项目类任务按 `记忆优先级.md` 的 🔴 L1 验收（合上材料能脱稿讲），🟡 L2 只要求看代码讲清思路；当天时间被压缩时，明确告诉用户"只保 🔴"。
- 每天**第一块固定复习错题本到期点**（按 `复习滚动机制.md`：八股 ≤8 个点/15 分钟、算法 ≤3 道、项目 ≤3 个点；任务表里写清"到期 X 个，🔴 a 个"），**最后 10 分钟回顾打卡**。
- 任务表末尾写一行**今日预估合计：X 分钟**（各块时长之和，含复习块与回顾块），它是耗时反馈的对照基准。
- 时间不够的那天：先砍学新块，保复习块——旧账遗忘比新内容欠债更贵。
- 周末或时间多的那天，安排一次整章复习 + 半套模拟 + **面经问答 15 分钟**：用目标公司/岗位的真实面经题快问快答，一题 2-3 分钟、只抓 🔴 L1 点能否脱口而出，不展开讲；卡壳的点当天入错题本。面经是考场采样不是新授课，目的是检验"真被问到时"的提取速度。
- 八股、算法、项目尽量每天都碰到；时间实在不够，至少保证算法不断。

## 输出要求

严格按 `references/templates/计划模板.md` 的顺序输出：

1. 倒计时看板
2. 三围诊断与时间配比
3. 三阶段总览
4. **今日任务表**（最重要，给得最细）
5. 本周剩余安排（只给主题和块数）
6. 里程碑检查点
7. 调整规则

- 第一次只细排"今天"，后面的天只给主题，避免一次输出太多把人吓跑。
- 用户说"继续排明天 / 排明天的任务"时，再按今日任务表的粒度细排下一天。

## 每日打卡与动态调整（打卡 → 调整 → 排明天）

固定四步，每次都走全：

### 1. 收打卡

- 每天学完让用户回报四件事：**完成了几块、卡在哪、每块负荷、当前疲劳度**。"卡在哪"的点当天入错题本（见 `复习滚动机制.md`）。
  - 块负荷三档：🔵 太松（没吃饱）/ 🟢 合适 / 🟠 吃力（赶或啃不动），逐块报或报最差的一块都行。注意不用 🟡（那是 L2 级别标记）。
  - 疲劳度三档：精力好 / 正常 / 饱和（学不动了）。**饱和状态下打的 0 分不评级、不入库**，该点白板复测移到次日早晨（睡后提取更准，也防疲劳污染错题数据）。
- 用户没主动回报就问一句："今天完成了几块？卡在哪？没卡点回个 0。"不追问情绪、不开批斗会；负荷和疲劳只问一次，不增加打卡负担。
- 收完打卡后，只要"耗时校准"未关闭，立刻按第 3 节发耗时反馈块。
- **负荷联动**：连续 2 天某类块报 🟠 → 次日该类拆小块或减 1 块；连续 2 天全 🔵 且完成率 ≥90% → 可提高验收档（🟡 L2→🔴 L1）或加 1 块（与耗时校准的加量动作合并，不重复加）。

### 2. 按完成率调整（欠债不许利滚利）

| 今日完成率 | 动作 |
|---|---|
| ≥ 90% | 明天正常排；连续 3 天 ≥90% 且错题本库存不涨，可给弱项加 1 块或加一轮单科模拟 |
| 50%-90% | 不补欠债，明天照常排——欠债是缓冲，不是高利贷 |
| < 50% 或连续 2 天没完成 | **明天任务量减半**：只保 1 个复习块 + 1 个最高优先级 🔴 块，先不断再谈足量 |
| 连续 3 天 < 50% | 说明初始时长不现实：**重算总账、重排三阶段**，并和用户确认真实可学时长 |

- 欠债块只允许**顺延一次**；顺延一天仍没完成，直接砍掉（内容会在后面章节碰到，或降级为 🟡 自学材料），不把昨天的债堆到明天。
- **减半日例外**：触发减半日（<50% 或连续 2 天没完成）时，昨日欠债**不顺延、直接砍**，把唯一一次顺延额度留给减半日当天的内容。
- 进度超前不加速赶工，多出来的时间给弱项或模拟面试。
- 面试日期变了：重算总账、重排三阶段，不在旧计划上打补丁。
- 用户中途说"不想学"：切换到 `状态教练.md` 的 PlanCoach 模式，先启动再回来执行。

### 3. 耗时反馈与动态校准（耗时信号 × 完成率信号）

目的：让预估时长越来越贴近用户的真实速度。**完成率掌加减量方向，耗时只做校准**，两个信号冲突时以下面的融合表为准。

**触发与交互**

- 反馈块格式按 `references/templates/计划模板.md`：显示今日预估合计，用户回复数字即提交（接受 `3h`、`3.5h`、`150m`、`2小时20分` 等写法，统一换算成分钟）。
- 用户在打卡消息里已主动报耗时（如"今天用了 3 个半小时"），跳过反馈块、直接给校准结论，不重复问。
- 用户可补一句归因，如"卡在算法 / 主要超时在八股"。
- 回"稍后"：在**第二天打卡时提醒补录一次**，再跳过就不再催，当天记录标"未报"。
- 回"关校准"：状态块置"耗时校准：关"，此后不问耗时、不自动调量（每块预估时长仍照常显示）；回"开校准"恢复。

**计算口径**

- 差异% = |实际 − 预估| ÷ 预估；实际 ≤ 预估 ×75% 记"偏快"，在 ±25% 内记"准点"，≥ 预估 ×125% 记"偏慢"。
- **阈值 25%，单日自动调量封顶 ±20%（约 1 个块）**。
- 题型系数分四类累计：八股 / 算法 / 项目 / 复习。当日只有总耗历时，按各类块的预估时长**比例分摊**；用户给了归因，则归因类分摊 70%、其余 30% 按预估比例分。
- 系数增量更新：`新系数 =（旧系数 × 旧样本数 + 当日该类实际÷该类预估）÷（旧样本数 + 1）`。
- **有效样本不足 3 天时只记录、不自动调量**，但要把当天差异口头告诉用户。
- **时长虚高预警（单日触发，不等 3 天）**：实际时长 ≤ 预估的 60% 时，当天明确提示"今日计划时长可能虚高"——完成率 ≥90% 则明天按真实可学时长重排块数（与融合表"偏快加量"合并执行）；完成率 <90% 只更新系数不加量，防止"少做了所以快"被误读为效率高。

**双信号融合表**

| 完成率 ＼ 耗时 | 偏快（≥25%） | 准点 | 偏慢（≥25%） |
|---|---|---|---|
| ≥ 90% | 可加 1 块，或同等块数提高验收档（🟡 L2 → 🔴 L1）；总幅度 ≤20% | 维持 | 明天减 1 块，或把最大的块拆成两块；总幅度 ≤20% |
| 50%-90% | **不加量**（快是因为少做，不是效率高），只更新系数 | 维持 | 块数维持、下调时长预算；连续 2 天偏慢再减块 |
| < 50% | 走减半日；耗时数据留作"连续 3 天 <50% 重算总账"时的真实速率依据 | 走减半日 | 减半日 + 提示用户真实可学时长可能低于最初估计 |

- 减半日当天不做耗时校准（样本只有 1-2 个块，不具参考性），记录但不参与系数更新。
- 系数只用于**时长换算和块数微调**，不改三围配比、三阶段打法这些上层结构。

**透明与用户否决**

- 触发调整时必须带原因话术：数据窗口（近 N 天）、差异% 或系数、具体动作（哪块加减、怎么拆），如"根据你最近 3 天实际耗时（算法平均多花 30%），明天算法 2 块 → 1 块并拆成两半做"。
- 不调整也要明说："差异 X%，在合理范围内，维持。"
- 调整输出后固定附一句可否决项："可回：维持原排 / 改成 X 块 / 只校准别调量。"用户手动决定当天优先；"只校准别调量"当天只更新系数、不动任务量。

**准确性报告**

- 每满 7 天（第 7/14/21… 天）打卡后、以及计划最后一天，输出一次预估准确性报告（格式见 `references/templates/计划模板.md`）：有效样本天数、平均绝对差异%、偏快/准点/偏慢天数、四类当前系数、下一周调整摘要、一条改进建议。
- 报告同时附**教学法一问**："这周哪个块你有过'懂了'的瞬间？是怎么发生的（动手做出来的/听讲/类比/画图）？"连续 2 周答案指向同一通道（如"都是自己动手"），就在后续计划里固化该通道（构造型用户固化任务先行，规则见 `任务先行规范.md`）；这是教学法自身的反馈闭环。
- 报告输出后，近 7 天耗时记录表可以清空——系数是累计值，存在状态块里，删行不丢模型。

### 4. 排明天 + 更新状态块

每次打卡结束输出「计划状态块」，让用户覆盖保存；跨会话和错题本表一样靠用户带回来（"把计划状态和错题本表发我"）：

```
## 📌 计划状态（x/x 更新）
- 倒计时：剩 X 天 ｜ 第 N 天/共 M 天 ｜ 阶段：打底/强化/冲刺
- 今日：计划 a 块 / 完成 b 块 ｜ 欠债累计 X 块
- 连续未完成：X 天 ｜ 本周完成率：xx%
- 错题本：库存 X 个（🔴 a 个）｜ 明天到期 X 个
- 耗时校准：开（阈值 25% ｜ 调量上限 20%）｜ 有效样本 N 天
- 校准系数：八股 ×x.xx ｜ 算法 ×x.xx ｜ 项目 ×x.xx ｜ 复习 ×x.xx（样本不足 3 天的标 "-"）
- 明天安排：X 块（复习 1 + 学新 n），主题：xxx
```

状态块后附「近 7 天耗时记录」小表（格式见 `references/templates/计划模板.md`），让用户与状态块、错题本表一起覆盖保存。

状态块之后直接给明天的今日任务表（粒度和第一天一致），**不等用户再问"明天学什么"**。排明天时同类块时长基准先乘该类系数（样本不足 3 天按基准时长），并在任务表末尾给出新的"今日预估合计"。

## 边界情况

### 有笔试（笔试在技术面前）

笔试和面试考法不同，计划必须差异化，不能只按面试排：

1. **算法块加量且限时手写**：每天算法从"做出来"升级为"限时做出来"（中等题 20 分钟），全程白纸 / 纯文本编辑器写，不依赖 IDE 提示。
2. **每天加 10-15 分钟选择题手感块**：八股从"脱稿讲"增加一个形态——快速判断选择 / 多选题，错题同样入错题本。
3. **笔试前 2 天安排 1 次限时笔试模拟**：按真实时长做一整套（选择 + 手撕），练的是时间分配而不是学新东西。
4. 笔试考完、面试未考：立刻把计划切回面试形态，减少选择题、恢复口述和项目深挖。

### 项目弱：没项目 / 项目水

三围里项目选"讲不清"或用户直说"没项目 / 项目很水"时，给两条路，不许装没事：

1. **优先包装现有项目**（课程设计、练手 demo、实习里的小模块都算）：先用 `读项目` 模式把它真的读懂一遍，产出函数地图和 🔴 L1 清单，再准备 3 个 STAR 故事。读过的才叫项目，没读过不许写简历。
2. **实在没有就突击 1 个迷你项目**：选和岗位匹配、2-5 天能做完且能讲透的（如前端手写 MiniVue / Promise、后端手写 RPC 框架）。排进打底或强化阶段，每天 1-2 块；冲刺期不再开新项目。
3. **底线**：不帮用户编造项目经历和贡献。讲不深的项目宁可只写一个，也不堆三个水项目——面试官多追一轮就穿帮，比没有更减分。
4. 模拟面试遇到项目还没准备好的用户：按 `模拟面试规范.md` 第二节处理，项目环节改成单科加练或当场提示先去读项目。

## 语气

- 像个靠谱的私教：目标明确、安排具体、每件事都能立刻动手。
- 不打鸡血，不制造焦虑。
- 计划是拿来执行的，不是拿来感动的：宁可每天少排一点能完成，也不要排满了天天欠债。
