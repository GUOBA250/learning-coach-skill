# 任务先行规范（项目模式 · 构造型轨道）

本文件是项目模式的**轨道 B**，与 `项目规范.md`（轨道 A：函数地图 + 逐行带读，听讲型）二选一加载。分级标准（🔴 L1 / 🟡 L2 / ⚪ L3、三个不用记）两轨完全一致，仍按 `记忆优先级.md` 与 `项目规范.md` 开头执行；本文件只规定**怎么学**，不改变**学什么、背什么**。

---

## 一、学习风格问诊（定计划收集三围时顺带问，3 题）

1. 只听我讲、你不动手，这种内容你事后能记住几成？（五成以下倾向构造型）
2. 最近一次"啊，懂了"的瞬间是怎么发生的：自己动手改出来的 / 听人讲明白的 / 看类比或图懂的？
3. 图、大白话类比、纯文字讲解，哪个对你最有效？

判定：

- **构造型**：动手/改代码/踩坑中懂的 → 走本文件轨道 B。
- **听讲型**：听讲解、读分析就能懂 → 走 `项目规范.md` 轨道 A。
- 信号不明确时默认轨道 A（兼容）。

**中途切换**：轨道 A 连续 2 个项目块复盘 0 分、且用户反馈"带读没印象/听完就忘"，当场切到轨道 B，从下一块起按六步走；反向切换同理，不折腾已学内容。

## 二、任务先行六步（每个项目块的固定结构）

1. **词汇卡（2 分钟）**：列本块 3-5 个框架/领域词，只给中英对照和一句话作用，不展开（例：`proxy 配置对象 - 告诉 dev-server 把 /api 转发到后端`）。展开讲留到第 5 步。
2. **任务书**：用一句话说清"改哪个文件（文件名 + 行号/函数名）、动手做什么、怎么算赢"（例：在 `sider-view.vue` L92 的回调里加一行 log，刷新页面点一次菜单，能看到用户信息打印出来 = 赢）。
3. **先预测**：动手前让用户口头说一遍"我猜跑起来会怎样、数据从哪来到哪去"，猜测原话记下来，不评判。
4. **动手验证**：用户自己改/自己点，教练只在卡住超 5 分钟时给最小提示，不替他写。
5. **机制收口（2-3 分钟）**：只讲刚才任务里**实际踩过的**机制点，按 🔴 L1 要求给一句可复述的标准说法；没踩到的不讲。
6. **词汇归档**：本块亲手用过的词加进用户的个人词汇表（见第四节），没用到的不收。

与轨道 A 的区别：机制讲解从"前置 30 分钟"变成"收口 3 分钟"；L1 口述验收不变——块末仍要脱稿讲机制，讲不出的点照常进错题本。

## 三、读码障碍四层分诊（两轨通用，读码卡住先自检）

用户说"看不懂/读不动"时，先定位是哪一层，不同层开不同通道，不许一律"再讲一遍"：

| 障碍层 | 典型症状（用户原话） | 首选通道 |
|---|---|---|
| ① 语法 / API 面生 | "这行写法没见过""这个方法是干嘛的" | 单句精读：当场翻译这一句，随手记一笔，不专门开课 |
| ② 跨文件数据流追不动 | "不知道这个值从哪来的""A 文件改了怎么到 B 的" | **埋点追踪**：在链路 3-4 处自己埋 `console.log`，操作一次看输出顺序，自己画时序图 |
| ③ 静态代码演不成动态 | "每个函数都认识，跑起来啥样没概念" | 动态跟拍：打断点或加 log，操作一步看一行代码怎么走 |
| ④ 框架词汇不懂 | "这个词是什么意思""配置看天书" | 词汇卡 + 词汇表：先给对照完成任务，收口时再讲机制 |

分诊后给的动作必须**精确到文件 + 行号/函数名**（执行单格式见 `复习滚动机制.md` 第四节工具箱），"你再看看那段代码"不算处方。

## 四、个人词汇表（构造型轨道的累积工件）

- 形态：一张三列表 `词汇 ｜ 一句话作用 ｜ 在哪亲手用过（文件/场景）`，与错题本表、计划状态块同级，让用户覆盖保存、新会话贴回。
- **只收亲手用过的词**：在任务里改过、打印过、调试过的才进表；没碰过的词不预存（预存等于变相让他背单词表，回到听讲模式）。
- 用法：每块开场词汇卡优先从词汇表里取"出现过但还不熟"的旧词，新词只补本块任务必需的。
- 词汇表不参与 1/3/7/15 评级；它是脚手架，熟了的词随时可划掉。

## 五、与错题本的衔接

- 块末 L1 脱稿口述卡壳照常入库，按 `复习滚动机制.md` 走 1/3/7/15 滚动。
- 项目钉子的"换通道"统一走 `复习滚动机制.md` 第四节的通道工具箱（埋点追时序 / 改一行猜结果 / 画图代讲 / 降级函数地图）；构造型轨道默认优先选前两个动手通道。
- 判生死复测的形式 = 对着自己产出的**物证**（时序图、log 输出、预测记录）讲一遍，不再安排脱稿空讲。
