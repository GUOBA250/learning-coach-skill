# 按需动手验证规范

本文件只用于用户选择动手，或项目问题需要代码/运行物证才能解释的场景；项目面试主线见 [项目规范](项目规范.md)。

## 启动前

读取已有 profile，用户已明确偏好时不重复问学习风格。先核对导学、面经和真实源码。一次只追一个可观测点，先给调用链站点地图，逐站推进，用户未理解不继续下钻。

## 验证流程

1. 词汇卡：仅解释当前任务会碰到的词，一句话说明作用。
2. 任务书：写清入口现象、要做什么、什么结果算验证；先给目录地图，不直接代做完整导航。
3. 预测：动手前让用户说预期结果；算法教学与单纯讲法展示不套此流程。
4. 验证：在运行环境操作或看日志，记录实际结果与预测差异。用户指定在 Trae 做浏览器验证时交给 Trae；不把静态读代码写成实测。
5. 机制：围绕物证解释发生了什么、为什么、如何解决，最后映射术语；提供节点与 STAR 口播。
6. 清理：撤本轮临时日志与改动，保留用户原有工作。记录物证和未完成项，先台账后快照。

## 卡点分诊

| 卡点 | 辅助手段 |
|---|---|
| 不认识语法/API | 解释当前一句，不扩成长篇源码课 |
| 跨文件数据流追不动 | 在关键站点埋日志，画时序图 |
| 不会把代码想成运行过程 | 一次操作、一步执行、对一个输出 |
| 术语过密 | 退回人话、类比，再映射术语 |
| 已反复口述仍不懂 | 换日志、画图或最小改动验证，不机械重复原稿 |

计时与同块补量见 [计划规范](计划规范.md)。主线提前完成且用户仍在正式学习时，余量用于同一问题加深；疲劳或明确休息立即结束，不强塞新功能。
