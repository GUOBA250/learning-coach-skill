# 项目规范

## 当前主线

先读 profile 的项目选择与教学法。锅巴的主线是“简历原文 → 面试官问题地图 → 面经对应 Q → 节点表与第一人称 STAR 口播”，Elpis 与 MiniVue 均适用。不得擅自改成按源码全量平推或默认白盒改造。

教学材料位于项目的 interview-prep/<项目名>/导学.md、面经.md 和 guide-frontend；从实际目录核实，不引用已删除的根目录旧导学。缺材料时按 [导学面经内置补建规范](导学面经内置补建规范.md) 补建必要内容。

每次只处理一个问题或一条因果链；说明为什么会被问，贴简历原文与面经 Q。示范基于面经事实，可调整节点和措辞；发现代码冲突时先给具体证据并修订材料，不背错实现。

## 交付与验收

- 先用“出什么事 → 为什么难 → 怎么办 → 术语映射”讲清，提供节点记忆表和完整第一人称 STAR 口播，两者缺一不可。
- 口播第一句准确说明贡献：跟课、独立实现或 AI 辅助落地，按已有核验记录；未知不代编。设计取舍可讲清不等于亲手完成。
- 🔴 L1 是机制、流程和取舍；🟡 L2 是具体实现；⚪ L3 是工具细节。代码和长路径不要求背。
- 正式复测不看讲稿，可以对着页面、日志、时序图等物证连续讲清因果链；漏核心钩子按 [复习滚动机制](复习滚动机制.md) 评分，不用眼熟或已运行代替理解。
- 每题评分后立即给标准答案，未满分先补丁再重述；原冷测分和辅导后重述分开记。用户停止时保留未完成记录。

## 代码验证是按需辅助手段

需要追数据流、埋点或改一行验证时才加载 [任务先行规范](任务先行规范.md)。不把动手作为所有面试口播的前置门槛。先给目录级地图，让用户导航；只有用户卡住时逐级提示文件、函数、行号。提供路径前核实实际存在。

浏览器眼见为实和演示自测的环境约束见 [进度与环境规范](进度与环境规范.md)；未实际操作不声称验证完成。探索埋点、临时改动结束后恢复，不碰用户原有改动。
