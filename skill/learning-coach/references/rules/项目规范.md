# 项目讲解规范

## 两条轨道（先问诊，再开讲）

读项目有两种学法，开讲前先按 `任务先行规范.md` 第一节做学习风格问诊：

- **轨道 A · 听讲型（本文件）**：函数地图 + 从底往上逐行带读——适合"听讲解就能懂"的用户，也是无明确信号时的默认轨道。
- **轨道 B · 构造型（`任务先行规范.md`）**：词汇卡 → 任务书 → 预测 → 动手验证 → 收口，机制只讲刚踩过的——适合"带读没印象、自己动手才懂"的用户。

两轨的分级、L1 口述验收、错题入库口径完全一致。中途发现轨道错配（连续 2 块 0 分且用户反馈"带读没印象"）按 `任务先行规范.md` 的切换规则当场换轨。

## 记忆优先级（先分级，再讲代码）

按 `记忆优先级.md` 给项目知识分级，**面试官不拿你的电脑，代码不用背，机制要背**：

- 🔴 **L1（背）**：整体机制、数据流、设计决策、"为什么这么做"——白板空手能讲 3 分钟。
- 🟡 **L2（懂）**：具体函数实现——看代码能逐行解释，不看代码能讲清思路。
- ⚪ **L3（认）**：工具函数、类型定义、边角分支——知道是什么、去哪找。

具体要求：

- 函数地图每行加「级别」列。
- 逐行讲解时，关键机制句前打 🔴，并说明"机制要脱稿讲，代码本身不用背"。
- 复习题和自查清单只收 🔴 L1 和 🟡 L2，按 L1 优先排序；⚪ L3 不考。
- 执行「三个不用记」：文件路径只记"文件名 + 干嘛"；错误码/配置项只记分类和原因、知道去哪查；API 拼写不背，只记它解决什么问题、为什么选它。

## 讲法顺序（轨道 A · 听讲型）

### 1. 先大白话讲这个文件是干嘛的

- 这个文件在整个项目里处于什么位置。
- 它解决什么问题。
- 为什么需要它。

### 2. 再一块一块拆，每块一行一行过

- 讲函数之前，先说"为什么要写这个函数"。
- 然后一行一行讲代码。
- 关键行要展开讲，简单行可以带过。
- 用户随时打断提问。

### 3. 顺序：从底往上

- 先讲不依赖别人的函数。
- 再讲依赖别人的函数。
- 遇到依赖之前讲过的函数，说"这个之前讲过"。

### 4. 每块结尾给复习题

- 只收 🔴 L1 和 🟡 L2、L1 优先，合计 4-8 个，按这块内容多少定，**不硬凑**；⚪ L3 不考。
- 格式：题号 + 级别（🔴/🟡）+ 问题 + 答案。
- 最后给带级别列的自查清单表格。

### 5. 如果用户看不懂

- 先按 `任务先行规范.md` 第三节「读码障碍四层分诊」定位是语法面生、数据流追不动、静态演不成动态还是框架词汇不懂，再开对应通道（埋点追踪、动态跟拍、词汇卡等），不要一律"再讲一遍"。
- 需要换讲法时：用更直白的方式、用生活例子类比、不要重复原话要换角度；构造型用户直接转轨道 B。

## 辅助要求

- 输出格式严格按 `references/templates/项目模板.md`（函数地图带级别列、每块结尾给 L1 清单）。
- 每讲一个函数之前，先告诉用户"为什么要写这个函数"，让用户有方向感。
- 如果函数之间有依赖关系，用"函数地图"先列出来。
- 用户如果说"讲的太晦涩"，你要重新用大白话讲一遍。

## 函数地图

讲一个文件之前，先列一个「函数地图」表格：

| 函数 | 级别 | 作用 | 依赖谁 |
|---|---|---|---|
| xxx | 🔴/🟡/⚪ | xxx | xxx |

然后按「从底往上」的顺序讲。讲完后给「本节 🔴 L1 清单」，列出用户必须能脱稿讲的 2-5 条机制/数据流/决策。

用户合上代码口述 L1 时卡壳的点，当场登记进错题本（每天上限 3 个项目点），按 `复习滚动机制.md` 走 1/3/7/15 天滚动；复习方式是脱稿讲机制，允许先降级为"看着函数地图讲"。
