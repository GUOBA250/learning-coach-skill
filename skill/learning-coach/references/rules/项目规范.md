# 项目讲解规范（索引）

项目模式统一走**任务先行**：词汇卡 → 任务书 → 预测 → 动手验证 → 机制收口，机制对物证讲因果链验收。完整规则（六步结构、读码障碍四层分诊、错题衔接、**工件先行估时**）见 `任务先行规范.md`，输出格式见 `references/templates/项目模板.md`；估时四步 / 读代码档 / 溢出池见 `计划规范.md`《工件先行估时法》。

## 记忆分级（任务先行共用）

按 `记忆优先级.md` 分级。面试官不拿你的电脑，代码不用背，机制要懂：

- 🔴 **L1（背）**：整体机制、数据流、设计决策、"为什么这么做"——对着物证（页面现象 / log 输出 / 时序图）能把因果链讲清，不考空手背原话。
- 🟡 **L2（懂）**：具体函数实现——看代码能逐行解释。
- ⚪ **L3（认）**：工具函数、类型定义、边角分支——眼熟、知道去哪找。
- 执行「三个不用记」：文件路径只记"文件名 + 干嘛"；错误码/配置项只记分类和原因、知道去哪查；API 拼写不背，只记它解决什么问题。

## 问诊

学习风格 3 题只在定计划时问一次，结论存 profile，项目模式直接用、不重问（题目与判定见 `任务先行规范.md` 第一节）。

## 错题衔接

机制点连续 2 个现象讲不清才入错题本，按 `复习滚动机制.md` 走 1/3/7/15 天滚动；项目点复习形式 = 对物证讲因果链，每天上限 3 个。

## AI 行为铁律（项目/任务先行场景，违反即事故）

1. **路径核实**：给用户的任何文件路径、行号/函数名锚点，给之前必须先用 Glob / Read / LS（或等权检索工具）核实真实存在；核实不到就明说"我没找到，先搜"，**禁止凭记忆编路径、编行号**。任务书里的"改哪个文件（文件 + 行号/函数名）"同样先核实再落笔。
2. **埋点与临时文件清理**：任务先行中为探索埋的 `console.log`、`tmp-explore*` 等临时代码/文件，任务验收时必须撤埋点、删临时文件；**"仓库无残留"是可观测验收标准的一条**，物证 = `git status` 干净 / 相关目录无 tmp 文件。操作细则见 `任务先行规范.md` 第二节末《埋点与临时文件清理》。
