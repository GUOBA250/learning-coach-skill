# 项目讲解规范（索引）

项目模式统一走**任务先行**：词汇卡 → 任务书 → 预测 → 动手验证 → 机制收口，机制对物证讲因果链验收。完整规则（六步结构、读码障碍五层分诊、错题衔接、**工件先行估时**）见 `任务先行规范.md`，输出格式见 `references/templates/项目模板.md`；估时四步 / 读代码档 / 溢出池见 `计划规范.md`《工件先行估时法》。

## 项目两分型识别（开项目块前先判定；v0.7.6 试行，10/12 白盒改造法首跑验证后转正）

开任何项目块前先判型，两型走两条主流程，禁止混用：

- **A 型【跟敲业务项目】**（如 Elpis）：跟教程敲出、能跑、有页面可操作 → 走《白盒改造法》。
- **B 型【他人源码项目】**（如 MiniVue）：框架 / 别人写的，用户本人没写过 → 走《故事点砍库法》。

**跟敲只产生"手的记忆"，不产生"决策记忆"**：跟敲时手在脑不在、跳过了全部决策点。禁止把跟敲代码当作"用户亲手写过的代码"直接套用 v0.7.3 机制讲解三段式第 1 段；**三段式仅在用户自己写过 / 亲手改造过该段代码之后适用**。A 型先用白盒改造法把跟敲代码改出自己的决策记忆，改造过的段落才允许进三段式。

## 导学/面经强制使用与诚实海拔核验（最高优先级铁律，先于本文件其他教学流程；v0.7.6 试行，10/12 首跑验证后转正）

1. **强制读导学**：每个项目块备课开场，教练必须先读该项目仓库根目录的《导学-{项目}.md》（project-guide 产物）——用它的"阅读路径表"定本块起点文件、"预计时间"栏作估时锚点（直接引用，不再裸估）、"checklist"作关账自测题。仓库没有导学文件时，**先补建再排点，禁止无地图裸讲**（v0.7.2"排程前查证"的升级硬闸门：10/8 估时事故与本次同源，都是有规矩没执行）。
2. **面经只当题库**：《面经-{项目}.md》用途 = 提供面试官主问做验收——用户走完白盒改造 / 故事点后，用对应 Q 题做脱稿验收；**严禁让用户照面经口播稿背诵**，口播稿只能在用户自己讲完后作对照补丁。
3. **诚实海拔核验闸门**：面经 / 简历中凡出现"独立完成 / 主导 / 我设计的"表述，启用前必须向用户逐件核验三档——**真做过**（能现场改造演示）/ **跟做复刻**（能讲原理，简历与口述口径写"跟教程实现"）/ **没碰**（禁用）。核验结论写入记忆；没碰的 Q 题与简历 bullet 一律标禁用，或先转"补强任务"真做出来后再启用。已核验案例（2026-10-11，已入记忆）：Elpis 签名加固 / supertest 测试重建 / webpack 修复 = **没碰，禁用**。
4. **估时锚点优先级**：同仓库《导学-*.md》"预计时间"栏是第 ⓪ 优先级锚点，高于《用时基准表》与其他锚点；同步落在 `计划规范.md`《排程前强制查证顺序》。

## 白盒改造法（A 型主流程；v0.7.6 试行，10/12 首跑验证后转正）

每个项目块 1 点，三步闭环，验收以"浏览器眼见变化"为准：

1. **操作**：用户亲手把功能跑起来点一遍（眼见现象，不许只读代码）。
2. **追链**：从现象追一条 3-5 文件调用链——教练**只给起点现象 / 入口文件**，严禁直接给完整路径和行号；用户自己顺链点进去，找错给方向性提示、不喂答案（提示分档见《导航寻宝规则》）。
3. **改造（最关键）**：用户亲手改一处（加字段 / 改校验 / 换渲染），跑起来亲眼看到效果。**改造成功 = 关账；只读懂没改造 = 不关账。**

项目跑不起来时，"把项目跑起来"本身就是第 1 个可观测点。A 型项目备 3-5 条核心流程，每条最终能脱稿讲"现象 → 经过哪些文件 → 为什么这么设计"。

## B 型源码项目：故事点砍库法（v0.7.6 试行，10/12 首跑验证后转正）

- **禁止按 Q&A 全集平推**（如 66 题逐个过，面试备料失焦）：开备前按"该技术栈面试高频追问"筛 **5± 个故事点**，其余模块统一降 ⚪ L3（知道是什么、不深读、不内疚）。
- 每个故事点四步：**看地图 → 自己找文件 → 合代码脱稿讲 2 分钟**（现象 → 为什么 → 关键 3 行）**→ 教练追问 2 个"为什么这样设计"**。
- 验收 = 脱稿 2 分钟 + 关键 3 行能认出；**不要行号、不通读、不要求默写源码**。导航过程同样走《导航寻宝规则》。

## 导航寻宝规则（通用；违反 = 教学事故；v0.7.6 试行，10/12 首跑验证后转正）

- 教练备课照常自己 Glob / Read 核实路径（v0.7.2 路径核实铁律不变），但**讲解时禁止把核实出的"路径 + 行号"原样端给用户**（10/11 定性：长期代做导航，用户从未练习自己定位代码）。
- 先给**包 / 目录级地图**（30 秒粒度，例：reactivity 管数据 / runtime-core 管渲染），用户自己从地图定位文件；找不到时按档提示，顺序固定：**目录 → 文件名 → 函数名 →（最后才）行号**。
- 任务书里"改哪个文件"只给到**入口文件 / 起点现象**级别；调用链其余路径与锚点由用户自己导航得出。`任务先行规范.md` 第 2 步任务书三要素中的"文件 + 行号/函数名"自本条起同样收窄。

## 记忆分级（任务先行共用）

按 `记忆优先级.md` 分级。面试官不拿你的电脑，代码不用背，机制要懂：

- 🔴 **L1（背）**：整体机制、数据流、设计决策、"为什么这么做"——对着物证（页面现象 / log 输出 / 时序图）能把因果链讲清，不考空手背原话。
- 🟡 **L2（懂）**：具体函数实现——看代码能逐行解释。
- ⚪ **L3（认）**：工具函数、类型定义、边角分支——眼熟、知道去哪找。
- 执行「三个不用记」：文件路径只记"文件名 + 干嘛"；错误码/配置项只记分类和原因、知道去哪查；API 拼写不背，只记它解决什么问题。

## 问诊

学习风格 3 题只在定计划时问一次，结论存 profile，项目模式直接用、不重问（题目与判定见 `任务先行规范.md` 第一节）。

## 错题衔接

机制点连续 2 个现象讲不清才入错题本，按 `复习滚动机制.md` 走 1/3/7/15 天滚动；项目点复习形式 = 对物证讲因果链，每天上限 3 个。

## AI 行为铁律（项目/任务先行场景，违反即事故）

1. **路径核实**：给用户的任何文件路径、行号/函数名锚点，给之前必须先用 Glob / Read / LS（或等权检索工具）核实真实存在；核实不到就明说"我没找到，先搜"，**禁止凭记忆编路径、编行号**。任务书里的"改哪个文件（文件 + 行号/函数名）"同样先核实再落笔。
2. **埋点与临时文件清理**：任务先行中为探索埋的 `console.log`、`tmp-explore*` 等临时代码/文件，任务验收时必须撤埋点、删临时文件；**"仓库无残留"是可观测验收标准的一条**，物证 = `git status` 干净 / 相关目录无 tmp 文件。操作细则见 `任务先行规范.md` 第二节末《埋点与临时文件清理》。
3. **溢出池自动续接**：主线可观测点达成后禁止直接做块末对账或切到别的块，必须先执行《任务先行规范》第 6 步「主线关账硬闸门」三看；该续不续、等用户提醒才续 = 事故，块末复盘必记。
