# 导学/面经内置补建规范（自包含兜底，v0.7.12）

## 何时使用

`项目规范.md`《导学/面经强制使用与诚实海拔核验》要求每个项目块备课前教练先读项目仓库根目录的《导学-{项目}.md》，用其"阅读路径表"定起点文件、"预计时间"栏作估时锚点、"checklist"作关账自测题；缺文件时"先补建再排点，禁止无地图裸讲"。

本规范解决"别人只装 learning-coach-skill、没装 project-guide，仓库也没有导学/面经文件"时的补建能力。**判定顺序**：

1. 项目仓库根目录已有《导学-{项目}.md》→ 直接读，不走补建；有《面经-{项目}.md》→ 当题库，不走补建。
2. 缺《导学-{项目}.md》或《面经-{项目}.md》→ **按本规范内置模板现场补建**，教练把两份文件生成出来，再按正常流程备课。**禁止无文件裸讲，也禁止因为缺 project-guide 就跳过导学闸门。**

补建产物与 project-guide 完整产物"效果差不多"：覆盖同等章节骨架、同等估时锚点、同等 checklist 与面试题库，只是正文由教练现场撰写（不经 project-guide 的简历重排等后处理）。若用户之后装好 project-guide，可用其产物整体替换内置补建文件，属正常升级，不冲突。

## 补建流程

1. 一次性向用户收集 5 条输入（缺就问，不让用户猜）：**简称 / 项目一句话描述 / 技术栈 / 求职方向 / 职责海拔假设**（真做过·跟做复刻·没碰三档；跟做复刻与没碰在简历与口述口径里如实标注，见 `项目规范.md` 诚实海拔核验）。
2. 教练自行 Glob / Read / LS 走查项目仓库，量出每个可观测点真实经过的文件路径、行数与机制数，产出结构与下表。
3. 按下方《内置导学模板》与《内置面经模板》全章节产出，落盘到 **项目仓库根目录**，命名为项目 interview-prep/<简称>/导学文件与对应面经文件。
4. 补建后按 `项目规范.md` 与 profile 的教学法执行；锅巴使用简历问题地图、节点表和完整STAR口播，动手验证按需辅助。

## 内置补建产物骨架（v0.9.1 起不再内置完整模板全文）

> 两个填充式完整模板已删除（与 project-guide 产物重复维护，2026-11-09 审计裁决）。补建时按以下**章节骨架**现场产出；正文仍须按仓库真实文件量出，禁止编路径、编行数、编面试题。

**项目 interview-prep/<简称>/导学文件章节骨架**：① 已确认输入（简称/一句话描述/技术栈/求职方向/职责海拔）→ ② 前置知识表（6-10 条，只填本技术栈高频追问）→ ③ 重点亮点与学习顺序（4-8 个，从入口机制到收口机制排序，每点给 2 个真实文件锚点）→ ④ 必备知识点 checklist（8-12 条，全是因果题不是背定义题）→ ⑤ 推荐阅读表（**唯一估时锚点**）→ ⑥ 核心原理解析（每亮点一条，问题→机制→落点三段，含真实函数名）→ ⑦ 关键设计决策表（3-6 条，备选/取舍/风险/验证）→ ⑧ 诚实声明（不编造量化指标）。

**对应面经文件章节骨架**：① 已确认输入 → ② 项目简介（1-2 句，简历可用）→ ③ 简历 bullet（一级 4-6 条，痛点+机制+硬约束+结果，可嵌套二级）→ ④ 简历→面试展开映射表（bullet 短标题 → 面试官主问 → 题号）→ ⑤ 面试问题（主问 + 每主问 2 追问；口播第一人称「我」、完整 STAR、每段 ≥150 字、题干不出现文件路径/私有函数名）→ ⑥ 源码证据索引表（主题→真实路径与内部符号→对应题号）。

## 落盘与维护约定

- 补建产物落**项目仓库根目录**，命名项目 interview-prep/<简称>/导学文件/对应面经文件。
- 内置模板是"能力兜底"，不是让 learning-coach 去复刻并长期维护 project-guide 的每一份产物；**凡用户已装 project-guide 或仓库已有产物，一律用现成的，不走内置补建**。
- 补建只生成骨架，正文必须教练按仓库真实行数/机制数量出后填写，**禁止凭空编路径、编行数、编面试题**；核实不到就明说"我先搜"，见 `项目规范.md` AI 行为铁律。
