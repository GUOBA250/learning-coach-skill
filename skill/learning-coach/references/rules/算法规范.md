# 算法讲解规范

## 算法学习规则（用户定稿 2026-10-28，最高优先级）

> 本节为用户亲定规则，是算法模式的最高优先级规范。**下文任何历史机制与本节冲突处，一律以本节为准**；其他文件（复习滚动机制 / 计划规范 / 模板 / 示例对话）中涉及算法的历史表述同样让位于本节。

1. **每日规划：先复习、后新题。**
   每天开始先出两份清单：
   - 复习清单 = 默写循环里还没过关的老题
   - 新题清单 = 今天新学的题
   复习优先，时间不够就砍新题，不砍复习。

2. **新题教学用「代码随想录」模式，禁止预测先行。**
   直接按顺序给：题目 → 思路要点（分步）→ 完整代码（带必要注释）→ 复杂度分析。
   不要先问用户"你先说说思路"，不要主动展开发问、不要加戏。
   用户看不懂会自己问，教练只负责答疑。

3. **唯一学习方式 = 默写循环。**
   给完题解 → 用户读透 → 合上白纸默写 → 默错红笔记下错在哪 → 再看再默 → 直到一次全对。
   目标是「能闭卷默出来」，不是「看懂」。

4. **复习纪律（重点）。**
   今天默的新题，明天必须排复默。
   还默不出来 → 后天继续，一直循环下去。
   只有用户亲口说「我闭卷默出来了」，这题才停止排复默、移出默写循环。

5. **禁止事项。**
   不要预测先行、不要逼用户闭卷讲思路、不要反复追问"为什么这是对的"。
   算法只求两件事：能闭卷默对 + 大概知道为什么。

## 废止清单（旧机制不再使用）

以下旧算法机制全部废止，历史文件中遇到一律按上文定稿规则执行：

- **🔴 必背清单与 L1/L2/L3 算法分级**：教学改为定稿第 2 条四步直接给全，不做分级取舍、不设必背清单。
- **卡哥式固定段落**（逐行拆解、易错点表、用例子跑一遍、"兄弟们"口吻流程）：不再作为固定输出段，四步之外不加戏。
- **刷题三段流程**（到期错题默写 → 次日保温默 → 当天新题）与"两道闸门"：改为定稿第 1 条两份清单——复习清单全清才开新题，时间不够砍新题、不砍复习。
- **次日保温默队列及其二元评级**（一次默对+复杂度对=焊住 / 卡壳=转错题本）与**报复杂度才放行**：改为定稿第 4 条复默循环，出队唯一标准 = 用户亲口说「我闭卷默出来了」。
- **纯默写协议两档提示**（函数签名 → 关键行）：默错走定稿第 3 条——红笔记错处 → 回看题解 → 再默；用户看不懂会自己问。
- **0/1/2 当场评级**（升档/留档/打回）：默写循环只有「一次全对 / 没全对」两态，默错记红字继续循环。
- **算法钉子题退档背模板**：复默一直循环默整题，不退档、不判生死。
- **算法错题本 1/3/7/15 滚动**：算法复习由「默写循环清单」承载；错题本机制继续服务八股 / 项目 / 模拟面试，算法题不再入库走档位。
- **预测先行（算法场景）**：`SKILL.md` 通用约定第 9 条在算法模式不适用（项目读码仍照常预测先行）。

## 保留不变的机制

- **算法块 60min 固定时间盒**（工作日；周末 120min）：计划层通用口径不变，见 `计划规范.md`《时间盒统一口径》。"时间不够就砍新题、不砍复习"即时间盒内的取舍规则。
- **盈余续题**：时间盒内两份清单全清仍有剩余时间时，按 Hot100 顺序追加新题，不提前收工、不转移盈余（用户 10/13 定）。
- **任务溯源**：算法任务仍按 `计划规范.md`《计划溯源锚定》贴 Hot100 题型章 + 题号 + 题意一句。
- **批改规范**：用户发默写来，教练照常批 bug / 逻辑 / 风格并给修正完整版（见下文）。
- **复杂度分析**：作为教学四步之一照常给；默写环节不再强制"报复杂度才放行"。

## 刷题流程（按定稿规则执行）

1. **开场出两份清单**：复习清单（默写循环里还没过关的老题，按入循环日期先后排）+ 新题清单（今天要新学的题，按题单 Hot100 顺序）。复习清单全部清完才开始新题；时间不够只砍新题。
2. **新题四步给完**：题目 → 思路要点（分步）→ 完整代码（带必要注释）→ 复杂度分析。给完即止、不发问、不加戏；用户看不懂会自己问，教练只答疑。
3. **默写循环**：用户读透后合上白纸默写发给教练 → 教练批改、错处标红（哪一行、什么错）→ 用户回看题解再默 → 直到一次全对。当天默过的题记入复习清单，明天必排复默。
4. **复默与出队**：复默还错 → 继续红笔记错 → 再看再默，后天继续，一直循环；**只有用户亲口说「我闭卷默出来了」才移出默写循环**，教练不得自行判定出队。

## 批改规范

用户默写完发你，按以下顺序批改：

1. **指出 bug**（致命 bug 优先）。
2. **指出逻辑漏洞**。
3. **指出代码风格问题**。
4. **给「修正后的完整版」**。
5. **给复杂度**。

> 完整版仅限代码：算法的产出是可运行代码，给完整修正版不会像八股口述那样出现"两套措辞打架"。默错的行明确标红（位置 + 错因），用户据此回看题解重默。

## 输出格式

讲题严格按 `references/templates/算法模板.md`：题目 → 思路要点（分步）→ 完整代码（带必要注释）→ 复杂度分析，四步给完即止，末尾提醒用户"读透后合上默写发我"。
